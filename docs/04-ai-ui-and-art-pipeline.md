# 让 AI 做界面与美术

> **一句话**：**界面用代码做，不要让它手绘图形**；让它做界面前，**必须给"设计风格"**；图出完了，**让它自己先看一遍**。
> 这三条都不是"技巧"，是**翻过车之后才总结出来的**（起因：为一个格子界面连续试错 8 轮，被评「元素堆砌太粗暴、没有设计感」）。
> 适用：用 AI 做游戏 UI / 网页界面 / 立绘与素材的人。

---

## 0 先说清楚：为什么这里最容易失望

跟 AI 做界面和美术，失望通常来自两件事，**而且都不是"它水平不行"**：

1. **你让它做的是它最不擅长的事** —— 手绘几何图形（画一个格子、一条边框、一朵云）。这类活儿在它的训练数据里**几乎没有参考**。
2. **你没给它"风格"** —— 它会给你一个**结构完整、但你不满意**的东西，然后你们开始一轮轮改细节（改到最后就是"元素堆砌"）。

下面每一条都对应一个具体的翻车现场。

---

## 1 ★★ 界面 / 图形：一律用代码画，别手绘

### 翻车现场

要做一个"格子"（迷宫/棋盘类界面），我走的是**手绘**路线：用 PIL 画渐变、手写 SVG path 描边框、再叠阴影和纹理。**来回改了 7–8 轮**，每轮都是"渐变 → 云纹 → 边框 → 阴影"往上糊，最后得到的评价是：

> **「元素堆砌太粗暴、没有设计感。」**

### 根因（关键的一句）

**手绘图形 = 插画活儿，比做 UI 难得多。**

模型的训练数据里有**海量优秀的前端代码** —— 布局怎么排、间距给多少、阴影怎么叠、字体怎么配，**都是成体系的做法**；但它**没有"你这个游戏的格子"**。你让它手绘，等于让它在一个它没见过的题目上瞎凑。

### 改法

| 阶段 | 用什么 | 为什么 |
|---|---|---|
| **设计阶段** | **HTML/CSS 单文件** | 零依赖、浏览器直接打开、可交互、可截图；**改间距/圆角/颜色 = 改一个变量** |
| **落地阶段** | 翻成引擎代码（我这边是 Godot 的 `Control` + `StyleBoxFlat` / `GradientTexture2D`） | 把已经看顺眼的设计**一比一搬过去** |

**CSS ↔ Godot 对照**（做游戏时用得上）：

| CSS | Godot 4 |
|---|---|
| `border-radius` | `StyleBoxFlat.corner_radius_*` |
| `box-shadow` | `StyleBoxFlat.shadow_size / offset / color` |
| `border` / `outline` | `border_width_*` + `border_color` |
| `linear-gradient` | `GradientTexture2D` |
| `opacity` | `modulate.a` |
| `transform: rotate()` | `Node2D.rotation` |

### 实证

**同一天、同一个需求**：HTML/CSS 版**一次就比手绘版好看得多**，而且此后的调整都是"改一个数字"，不再需要重画。

> **可迁移的判据**：如果你发现自己在"给一个形状加细节"（加边框、加阴影、加纹理），**停下来 —— 那是插画思路**。改成"写一个 CSS 类"。

## 2 ★★ 提示词**必须写"设计风格"**

有一句被反复引用的话，说得比我准：

> **「你在提示词中没有要求设计风格，如果心中已经有预期，那 AI 生成的页面虽然结构完整，但是很可能并不满意。」**

⇒ **让它做界面前，必须给三样**：

1. **参照物**（截图 / 网址 / "像 X 那种感觉"）—— **这是决定性输入**，AI 编不出来；
2. **设计系统数字**（主色 / 圆角 / 阴影 / 间距，**哪怕只给两三个**）；
3. **这次只改哪一处**（例："只把间距从 14 改成 9"）。

**分工**：**审美判断归你**；AI 只保证**不出硬伤**（糊了 / 盖住了 / 比例错 / 元素堆砌）。

### ★★ 画面元素一律用**正面句**描述

**不要写"不要 X"** —— **越强调越容易把 X 生成出来**（等于把 X 顶到最前面）。

- **实战反例**：为了纠正上一版画出的"墙"，我在提示词里**连写三处**「绝对不要画墙／墙从不出现／整屏看不到任何墙」，当场被叫停：
  > 「**部分关键词你先别强调，越强调越错，直接不要提。**」
- **正解**：**只描述"要什么"** —— 例："两个格子相通时，就在空隙里画一截通道条把它们连起来；没有通道条的地方保持画面底色即可。"**全篇不出现那个词**。
- **同理：强调记号别堆** —— 满屏 `★★` / `【】` / "绝对" / "从不"，会让 AI 抓错重点。**规格数字保留，语气放平。**

## 3 载体结论：HTML/CSS 是 AI 的"设计语言"

- 有文章**标题即结论**：《AI 生成 UI 设计新范式：**用 HTML/CSS 作为 AI Agent 的设计语言**》。
- 网页端生成工具（如 v0.dev）的定位被总结为：「用文本直接生成 React + Tailwind 代码……**本质上不是设计工具，而是前端生成器**」。
- **Tailwind 流行的真实原因**：原子类让 AI **少写 CSS、少出错** —— 而"样式写错"正是 AI 生成 UI 的主要翻车点。

⇒ 所以流程可以是：**先用 HTML/CSS 定设计（改得快、看得见）→ 再翻成你要的落地形态**。

## 5 本地出图：ComfyUI

### 5.1 为什么用本地

**免费、离线、风格可控**、批量跑不限量。代价是**慢**（我这台单张 60–120 秒）和**吃显存**。

### 5.2 装在哪

**一律装在数据盘，别放系统盘**（模型动辄几 GB，一个 SDXL 三件套就要 10 GB+）。
典型结构：`<数据盘>/ComfyUI_windows_portable/`，启动脚本在根目录，服务端口 `8188`。

### 5.3 关键组件（SDXL 系为例）

| 件 | 作用 | 备注 |
|---|---|---|
| **主模型**（checkpoints） | 决定画风 | fp16 safetensors，6.9 GB 级 |
| **CLIP ×2** | 文本编码器 | 从基础模型仓的 `text_encoder` 取 |
| **VAE** | 色彩解码 | 从同一个仓取 |
| **参考图插件 + CLIP-Vision** | 用参考图控风格 | ⚠️ 文件名要**按预设命名**，否则加载器找不到 |

> **量化版（GGUF）慎用**：我用 GGUF 量化路径出图**明显发糊**（清晰度指标 4 vs fp16 的 16）⇒ 直接上 fp16。
> 顺带一条目录坑：GGUF 的 `unet_name` 读 `models/diffusion_models/`，**不是** `checkpoints/`。

### 5.4 出图脚本

```bash
python local-generate.py "prompt" <输出路径> [宽 高] [seed] [ckpt]
# 例：竖版立绘 832x1216
python local-generate.py "portrait of ..., sharp detailed face" out.png 832 1216 42 ckpt
```

- 默认参数：steps 28 / cfg 6.0 / euler normal / 内置负面词；
- **风格提示**：角色描述 + 服装 + 背景 + `sharp detailed facial features, upper body`。

### 5.5 ★ 性别标签铁律（真实事故）

danbooru 系的动漫模型**默认偏女性**。我漏了性别标签，结果**男性角色立绘全部变成女性**（"某某变女掌门"）。

⇒ prompt **必须**带：`1boy/1girl, solo, adult male/female, masculine/feminine`；男性再加 `beard` 等特征词强化。
⇒ 另：**覆盖前保留原图**（输出目录里有历史备份，**别急着删测试图**）。

## 6 ★★ 跑图前，先看显卡在不在被别人用

**这是我最贵的一次教训。**

**现场**：6 GB 的卡上，**你的游戏 + 我的出图任务装不下**。我连出 4 张后，第 5 张**超时 180 秒**、出图进程**崩掉**，而**僵死进程还占着卡不放**（`5796/6141 MiB · GPU 100%`）。清掉之后才回落到 `1058 MiB / 34%`。

**判据（跑图前必查）**：

```bash
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv
```

**看见别的程序在用卡，就不要跑图** —— 既卡别人，图也出不来。

**⚠️ 更阴的一条**：我的启停小工具 `comfyui-ctl status` **把"僵死但仍占卡"的进程报成「没在跑」** ⇒ **别只信状态工具，要交叉 `nvidia-smi`**。

## 7 ★★ 出图后，让 AI 自己先看一遍

### 7.1 为什么

生成的图如果只是**磁盘上的一个文件**，就必须有人肉把它看一遍 —— **否则 AI 会把废图交给你**。

### 7.2 我实际漏掉过的（都是"人眼看一眼就发现"的）

- 头发跑成**紫色**（我只写了"红剑穗"）
- **三个手**（手部崩坏是扩散模型的经典问题）
- **剑没拔出**（一直画成在鞘里）
- 背景跑到**教堂**（写了 green robe，模型自由发挥成西式建筑）
- 角色**绿头发**（提示词里的 "green robe" **污染到发色**）
- 气质跑成"**邪魅**"（`confident smirk` 被渲染成冷笑）

### 7.3 ★ 三种"看图通路"（别混）

| 图在哪 | 怎么看 |
|---|---|
| **对话里**（你贴给它的） | **模型原生视觉，直接看得见**，不需要任何工具 |
| **磁盘上**（生成结果 / 截图 / 素材） | 用**读图工具**把文件送进模型上下文 |
| 两者都不是 | **问人**能不能把图贴进对话 |

> ⚠️ **不要用"外部小模型转述"当前者**。我一度把图交给本地视觉小模型转述，结果：**慢、不准**，更糟的是它**反过来让 agent 形成"我看不见图"的错误自我认知**（当天因此误判两次）。
> **模型本来就有眼睛，别给它配一副二手的。**

### 7.4 验收判据表（示例，按你的项目改）

| # | 项 | 合格 | 违反 |
|---|---|---|---|
| 1 | 头发 | 黑色系 | 明显紫 / 蓝 / 银 / 粉 |
| 2 | 持剑 | **已出鞘的裸刃**、完整入画 | 在鞘里 / 被画框裁掉 |
| 3 | 手 | 数量正常、手指不融合 | 多手 / 融合 / 缺指 |
| 4 | 背景 | 素背景 | 具体场景（尤其与设定不符的西式建筑） |
| 5 | 气质 | 少年意气 / 自信 | 邪魅 / 阴狠 / 苦情 |

**标准流程**：

```
出图 → 存进工作区 → 自己看一遍 → 不合格 ⇒ 自己重出（不交付）
                              └ 合格 ⇒ 才拿给人挑（★ 品味仍归人）
```

### 7.5 三条工程坑（与工具无关，仍然有效）

1. ★★ **"重出给人看"的图必须换文件名** —— 同名文件替换后，**前端会显示缓存的旧图**（我一天内连踩两次）。凡重出，文件名带**版本号或时间戳**。
2. ★★ **改图/生成类交付前，必须程序验关键属性** —— 我用抠图节点翻过车：它的输出是「**背景＝白**」的蒙版，直接当 alpha 用 ⇒ **把人抠掉、留了背景**。
   ⇒ 正确链路：`加载图 → 抠图(只出蒙版) → ★ 反相 → 合成 alpha → 保存`；交付前用几行代码核对：**四角是否透明、中心是否不透明、人物占比是否合理**。
   ⇒ 本质：**有自查工具 ≠ 会自查**。
3. ★★ **真窗口截图会留孤儿进程** —— 我用"只取前 N 条"的写法截管道，导致 PowerShell 以为结束了、而**引擎进程还活着**（一晚攒了 6 个，机器变卡）。
   ⇒ 规矩：截图后**必查进程**并清理；**别用"取前 N 条"掐管道**；多张图**同一个进程批处理**。

## 8 矢量纹样：AI 出图 → 矢量化

**不要手写 SVG path**（巨难画好）。可靠链路：

```
AI/手绘出图 → 裁切 → 二值化（必要时形态学加粗） → potrace 矢量化 → SVG
```

- `potrace`（npm 上纯 JS 版）**无原生依赖、可用**；SVG 转 PNG 预览可用 `@resvg/resvg-js`。
- ⚠️ **三个必踩的坑**：
  1. **素材若是透明底 PNG**，用"转灰度"当形状依据会把**透明区变成黑色** ⇒ 图形与背景**判反**（我因此连废四次）⇒ **用 alpha 通道判断形状**；
  2. **potrace 输出的是"填充形状"** ⇒ 用 `fill`，**不要用 `stroke`**（会描成双细线，形状全丢）；
  3. **路径要复用**：放进 `<defs>` 用 `<use>` 引用，否则 N 个格子各嵌一份，同一个 SVG 从 **38 KB 涨到 950 KB**。
- ⚠️ **尺寸与细节是矛盾的**：给"大尺寸展示"画的纹样，缩到 32–56 px 的格子里会**糊成一块** ⇒ **小格用简化纹样**，复杂纹样留给大尺寸装饰。
- ⚠️ **线色要看底色**：格面是米白渐变时，**白线贴上去几乎看不见**（我连踩两次）⇒ **深底用白、浅底用"比底色更深的同色系"**。

## 9 一页速查

| 你要做的事 | 别做 | 该做 |
|---|---|---|
| 做界面 / 格子 | 手绘 SVG / 用绘图库画形状 | **HTML/CSS 写出来** → 再翻成引擎代码 |
| 让 AI 做界面 | 只说"做个好看的界面" | 给**参照物 + 设计数字 + 只改哪一处** |
| 描述画面元素 | 写"**不要** X"（越强调越容易生成 X） | **只写"要什么"**，全篇不出现那个词 |
| 强调重点 | 堆 `★★` / "绝对" / "从不" | 规格数字保留，**语气放平** |
| 出图 | 直接跑（不管显卡） | 先 `nvidia-smi` 看卡；工具状态**要交叉验证** |
| 人物立绘 | 忘了性别标签 | `1boy/1girl + solo + adult male/female` |
| 出完图 | 直接交给对方 | **自己先看一遍**，不合格自己重出 |
| 重出图 | 覆盖同名文件 | **文件名带版本/时间戳**（否则前端显示旧图） |
| 抠图 | 拿蒙版当 alpha | **反相后**再合成；交付前程序验四角/中心 |
| 画矢量纹样 | 手写 path | 出图 → **potrace**（注意 alpha、`fill`、`<use>` 复用） |
