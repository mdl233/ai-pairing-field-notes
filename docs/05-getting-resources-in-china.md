# 在国内网络里搞到模型、插件与工具

> **这不是"翻墙教程"，是一份"通道与校验"的实测记录。**
> 模型权重、插件包、命令行工具大多托管在境外 —— 在普通家庭宽带（不挂代理）下，**"拿得到"本身就是一道关**。
> 本篇只讲**怎么拿、怎么验、拿不动怎么办**；这些工具**怎么用**见 `04` 与本仓其它篇。
> ⚠️ 所有"可用性"结论**只代表我这台机器、这个网络、这一天**（2026-10）—— 网络策略会变，**请以自己的实测为准**。
> **时效**：复核 **2026-10-08**；带 🔄 的条目会随环境变化，用前请按文中命令复核（其余条目自带日期与出处）。
> 🔄 **本篇时效敏感区**：§1 的**通道实测表** · §6 的**本地小模型**（速度与显存数字）—— 网络策略与模型版本都会变，那两处**只代表作者那台机器、那一天**。

## 1 通道实测表（先看这张，能省你半小时）

| 通道 | 我这台机器 | 怎么用 |
|---|---|---|
| `registry.npmjs.org`（npm 官方） | ❌ **被墙**（`fetch failed`） | 换镜像，见下行 |
| `registry.npmmirror.com` | ✅ **node 可直连** | 元数据 `…/<包名>`；包体 `…/<包名>/-/<包名>-<版本>.tgz` |
| GitHub 直连（`git clone` / Release） | ❌ **连接被重置** | 走代理镜像，见 §2 |
| `gh-proxy.com` / `ghproxy.net` | ✅ 可用 | `git clone` / Release `.tgz` / 单个原始文件 |
| `raw.githubusercontent.com` | ✅（配镜像） | 取仓库里的单个文本文件 |
| `cdn.jsdelivr.net` + `data.jsdelivr.com` | ✅ **浏览器可访问** | **列包内文件**：`data.jsdelivr.com/v1/package/{gh,npm}/<包>[@版本]/flat`；**取源码**：`cdn.jsdelivr.net/gh/<owner>/<repo>@<ref>/<路径>` |
| `huggingface.co`（模型） | ⚠️ 慢 / 易断 | 换 `hf-mirror` |
| `hf-mirror` **大文件** | ⚠️ **>1 GB 会截断** | 分段下载，见 §3 |
| `pypi.org` | ⚠️ 慢 | 清华镜像 `pypi.tuna.tsinghua.edu.cn/simple` |
| `civitai.com` / `itch.io` | ❌ 需登录或需代理 | **交给人**，见 §4 |

**一句话纪律**：**先试直连 → 失败就换正规镜像 → 镜像也不行就交给人**。
**不要**反复重试同一个不通的地址，**不要**退而去找可疑的第三方镜像站。

## 2 GitHub 系：两个开关 + 一条命令

```bash
# 克隆仓库（走代理镜像；并把 TLS 后端换成 openssl）
git -c http.sslBackend=openssl clone https://gh-proxy.com/https://github.com/<owner>/<repo>.git

# 取 Release 里的包
https://gh-proxy.com/https://github.com/<owner>/<repo>/releases/download/<tag>/<包名>.tgz
```

- **为什么要 `-c http.sslBackend=openssl`**：Windows 上 Git 默认走 `schannel`，在代理镜像下**证书链报错**；换成 openssl 后端即通（这条我踩过一次，前后折腾了十几分钟）。
- **不想 clone 整个仓库**、只要几个文件时，用 jsdelivr 更省事：它能把仓库当静态文件服，还能**列出包内所有文件**（先看清单再决定拿什么）。
- ⚠️ 浏览器能访问 ≠ 命令行能访问。我这台机器上**浏览器的可达性明显好于 node/pwsh 直连**（`registry.npmjs.org` 就是典型：浏览器能开，node 报 `fetch failed`）⇒ **判断"能不能下"要分工具试**。

## 3 大文件：截断是最阴的坑

**症状**：一个 6.9 GB 的模型显示"下载完成"，加载却报文件损坏。

**根因**：镜像对大文件会**静默截断** —— 不报错、不中断，只是少了几个字节。

**处置**：
1. **>1 GB 的文件用分段（range）下载**，逐段追加；
2. **下完立刻校验**（见下）；
3. 加载报损坏时，**先核文件字节数**，别先怀疑推理框架。

**校验纪律（所有下载都适用）**：
- 能拿到官方哈希就 **SHA-256 对拍**；
- 拿不到哈希，至少核**字节数**与发布页一致；
- ⚠️ **"下载完成" ≠ "文件完整"** —— 这句话值一个 6.9 GB 的教训。

**gated（需授权）仓库**：报 401/403 不是你的网络问题，是仓库要授权。**换一个同内容的非 gated 镜像仓**通常更快（例：`stabilityai/sdxl` 是 gated，`stabilityai/stable-diffusion-xl-base-1.0` 可直接取）。

## 4 ★ 拿不动就交给能拿的人（这条最省事）

如果一条通道对你不可用（需要登录、需要验证码、需要代理、需要付费），**别硬扛，也别悄悄放弃**：

> **把请求一次给全四样：① 资源名 ② 直链 ③ 目标目录 ④ 体积。**
> 对方（能挂代理的同事 / 朋友 / 另一台机器）下好丢到约定目录，**你负责入库、归位、校验**。

**为什么值得单列一条**：我这边的模型权重、civitai 素材、itch.io 上的资源，基本都是这么拿到的。**"我的线路不通"是分工，不是麻烦** —— 反复重试浪费的时间，比开口问一次贵得多。

## 5 插件：找 → 装 → 验

### 5.1 找：插件市场比自己翻仓库快

社区有插件目录站（**带中文界面**），每张卡片会标：包名 / CI 实测结果（"在某版本上装过并验证"）/ **可直接复制的安装命令** / 活跃度。

> **它最大的价值不是省搜索**，而是**它同时是"装配语法"的权威参考** —— 站内文档直接教当前版本的写法。
> 有的站还提供"目录插件"：装上后直接对 agent 说"给我装个记忆插件"，**由它自己去目录里找** —— 把"找插件"也外包出去。

### 5.2 装：四步，少一步都不算完

```bash
dsh plugin --profile <档案> add <包名>[@版本]   # ① 装（写档案的 package.json）
dsh plugin --profile <档案> version-exemptions  # ② 看 peer 告警 / 现有豁免
（重启 DSH：桌面端退出后重新打开）      # ③ 重启（重建插件注册表）
node <工作区>/50-tools/dsh-plugin-doctor.mjs    # ④ 体检（零 pending / 零 skipping 才算成）
```

### 5.3 三道坎（都是踩过才知道的）

1. **peer 兼容门** —— 插件的依赖范围与当前宿主不符时，**它会"静默跳过"**：站点起得来，但功能整块没有（fail-late，最难查）。逃生阀是**精确版本豁免**（`allow-version … --accept-risk`）；⚠️ 官方原话是**可能导致崩溃或数据损坏**，只在隔离环境或确有必要时用。
2. **名字解析** —— 手工安装时，如果插件自带的配置里写的是**不带前缀的短名**，会 `failed to import`；建一个同名别名目录即可。
3. **必须重启** —— 不重启则新插件没进注册表、删掉的插件又都在内存里引用着 ⇒ **GUI 白屏**。

**⚠️ 一个副作用**：**跑任何 `plugin` 子命令，事后都要 diff 一遍档案里的依赖与挂载清单** —— 有一次我只跑了一条"查看豁免"的命令，事后发现**一个早已刻意摘掉的插件被塞回去了**。

### 5.4 兜底：手工装三步（零包管理器）

当官方安装会触发整树重建（宿主正在运行时**不要做**）时，走手工：

1. 从 **npmmirror** 取 `.tgz`；
   ⚠️ 解包时注意：Windows 盘符（`F:`）会被当成**远程主机名** ⇒ **先切到目标目录、用相对文件名**。
2. 解包到**稳定位置**（不要放在会被清理的临时目录），再复制进档案的 `node_modules`；
3. 在档案 `package.json` 里加 `dependencies`（指向稳定位置）**和**挂载清单一条，然后**校验 JSON 无 BOM**。

## 6 本地小模型：**只推荐，不避雷**

> **本篇这一节的态度很明确**：**只讲"我在我的机器上怎么用"，不下"某模型不行"的判决。**
> 因为**决定本地模型能不能用的，往往不是模型，而是你的环境**：显存多大、内存多大、运行时哪个版本、有没有别的程序在占卡。
> 同一个模型在 6 GB 卡上"慢到没法用"，在 12 GB 卡上可能"秒回"。

### 6.1 我的配置参数

**完整配置表在仓库 [README](../README.md) 的「作者的环境」一节** —— 同一事实只在一处维护（这也是 `03` §3 讲的规矩）。
这里只补一个**和本节最相关**的数字：

| 项 | 值 |
|---|---|
| 本地模型运行时 | **ollama 0.35.1** |
| 参考实测 | `qwen3:4b` → **51.8 t/s · 100% GPU · 显存 3.1 GB · 1021 tokens / 23.6 s** |

> ★ **请把这些数字当成"一个人的体检报告"，不是"标准答案"。**
> 你的机器不一样，结论就可能完全相反 —— **唯一可靠的判据是你自己跑一次**。

### 6.2 我拿它们干什么（用途分工，不是排名）

| 模型 | 我拿它做什么 | 为什么 |
|---|---|---|
| `qwen3:4b` | 通用问答 / 结构化抽取（"这份文件里关于 X 是怎么规定的"） | 4B 级在这张 6 GB 卡上**能整个放进 GPU**，速度可用 |
| `hy-mt2-7b` | **翻译** | 专用翻译模型，中英互译比通用模型稳 |
| `nomic-embed-text` | **向量 / 聚类**（把几百条资料按主题归类） | 小（274 MB）、快、不占卡 |

### 6.3 我自己总结的三条经验（**都带"在我这儿"限定**）

1. **选型先看显存，再看参数量。** 我这台是 6 GB ⇒ **4B 级最舒服**（100% 上 GPU）；7–8B 级要部分 offload（慢但能跑）。更大的我没试过，**也不替别人下结论**。
   **判据命令**：`ollama ps` —— 看 `PROCESSOR` 列。`100% GPU` 顺；出现 `CPU` 就是在 offload（慢的根源往往在这）。
2. ★★ **"一次实测"不是"判决书"—— 换版本可能差十倍。**
   真实经历：2026-09 我在 ollama **0.33.3** 上测某个 4B 模型，只有 **~5 t/s**，于是把它记成"本机不可用"；2026-10 升到 **0.35.1** 复测同一台机器、同一个模型 —— **51.8 t/s**。
   ⇒ 结论：**任何"某模型在本机不行"的说法，都必须带版本号与日期，并且值得重测一次**。
3. **本地模型当"导航"，不当"决策者"。**
   它适合：定位 + 抽取（"这文件里规则是怎么写的"）。它不适合：判断、权衡、跨文档强关联（那是 API 大模型的活）。
   ⇒ 它**省的是钱**（把原文换成"结论 + 出处"），**不是时间**（比直接搜索慢 100–1000 倍）。

> **为什么"省钱"值得做**：长会话里**成本大头是"每一步把之前读过的内容重发一遍"**（实测占比 90%+）。
> 让本地模型在源头拦掉"原文进上下文"，省下的是这部分重复传输。

## 7 批量找资料：让脚本干活，大模型只读摘要

需要"一次性参考几十~几百条外部数据"时（榜单、评论、同类产品清单…），**不要把网页一条条喂给大模型**：

```
脚本爬取 → 清洗 → 聚类（全部本地、零 LLM token）
                    ↓
            只把"聚类摘要"给大模型
```

- **为什么**：几百条原始数据全塞进上下文，既贵又乱；聚类后大模型看到的是**几组主题 + 代表样本**，信息密度高得多。
- **实测效果**：抓取、清洗、聚类全程**不消耗任何大模型 token**；大模型只花在最后读摘要那一步。
- **同理适用于本地大文件**：先用脚本/grep/本地模型定位，**只把相关片段**交给大模型。

## 8 附：三个配套小工具（已随本仓发布）

| 本仓 [tools/](../tools/) 里的文件 | 原名 | 干什么 |
|---|---|---|
| [`local-generate.py`](../tools/local-generate.py) | `gen_sdxl.py` | 走**本地** ComfyUI 出图（免费、离线） |
| [`cloud-generate.py`](../tools/cloud-generate.py) | `gen_seedream.py` | 走**云端 API** 出图（收费；效果更强） |
| [`comfyui-ctl.mjs`](../tools/comfyui-ctl.mjs) | `comfyui.mjs` | ComfyUI 的 `status / start / stop`（幂等启停） |

**关于命名（一个真实的教训）**：原文件名里的 `gen_` 是 generate 的缩写，**后缀是"模型/后端名"而不是功能名** ——
`SDXL` = Stable Diffusion XL（一个本地模型），`seedream` = 某个云端生图模型的名字。
⇒ **这种命名对作者方便、对读者不友好**（看不出"一个走本地、一个走云端"），所以发布时改了名。

**发布前做的两件事**（任何人都该做）：
1. **去掉凭据引用** —— 改成从环境变量读（`cloud-generate.py` 读 `ARK_API_KEY`），脚本里不留任何 key、也不读别人的私有凭据文件；
2. **路径参数化** —— 环境变量 + 命令行参数优先（`COMFYUI_ROOT` / `COMFYUI_URL` / `--root` / `--url`），不留作者本机的绝对路径。

> 顺带修掉一个**真问题**：原脚本把默认后端写成了量化版（GGUF），而它自己的注释和手册都说量化版**弃用**（出图发糊）——
> **默认值指向了已被否定的路径**。发布版已把默认改成 fp16。

## 9 一页速查

| 你遇到的情况 | 怎么办 |
|---|---|
| npm 装不上 | 换 **npmmirror**；浏览器能开 ≠ 命令行能通 |
| GitHub clone / 下载失败 | 走 **gh-proxy**，并加 `-c http.sslBackend=openssl` |
| 只要仓库里几个文件 | 用 **jsdelivr**（能先列文件清单） |
| 大模型文件加载报损坏 | 先**核对字节数**；>1 GB 要**分段下载** |
| 仓库 401/403 | 是 **gated**，换同内容的非 gated 镜像仓 |
| 下完不知道对不对 | **SHA-256 / 字节数**对拍；"下载完成"≠"完整" |
| 需要登录 / 需要代理 | **交给人**，给全四样：资源名 · 直链 · 目标目录 · 体积 |
| 插件装完没反应 | 看 **peer 门是否静默跳过**；**必须重启**；再跑体检 |
| 本地模型好慢 | 先 `ollama ps` 看是不是 **100% GPU**；再考虑**升级运行时**后重测 |
| 几百条外部资料 | **脚本爬 + 聚类**，大模型只读摘要（0 token 完成 90% 的活） |
